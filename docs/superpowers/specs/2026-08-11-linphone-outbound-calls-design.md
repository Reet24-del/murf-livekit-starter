# Linphone Outbound Farm Advisory Design

## Goal

Add a Day 6 outbound-calling workflow that lets Kisan Sahayak call a user-controlled Linphone account, identify itself and the call purpose immediately, deliver a live rain advisory, honor opt-out requests, and end or fail gracefully.

## Provider and scope

The first supported route is LiveKit SIP with Linphone. It follows the challenge's official no-Twilio fallback and calls a Linphone username through an outbound SIP trunk at `sip.linphone.org`. The metadata and destination validation also accept E.164 numbers so a Twilio trunk can be substituted later without changing the agent.

The implemented campaign is a rain and crop-safety advisory. Each dispatch includes the destination, district, optional crop, opening language, consent confirmation, and whether the operator deliberately overrode quiet hours for a controlled demonstration. The agent reuses the existing live Open-Meteo integration to fetch current conditions and today's rain probability after the recipient answers. It never invents weather data when Open-Meteo is unavailable.

## Consent and call safety

The dial command requires an explicit `--consent-confirmed` flag, which means the destination belongs to the operator or the recipient has agreed to receive the call. It rejects malformed destinations, blocks destinations that previously opted out, and permits calls only between 08:00 and 20:00 Asia/Kolkata unless the operator deliberately supplies `--override-quiet-hours` for a controlled demonstration.

These checks run before a LiveKit room or dispatch is created. The outbound worker validates the metadata and opt-out state again so direct dispatches cannot bypass the important safety rules.

## Opening and language behavior

The first two spoken sentences are fixed rather than generated by the model.

English:

> Hello, this is Kisan Sahayak calling with a live rain and crop-safety advisory for your farm. Say “stop calls” at any time and I will opt you out of future calls.

Hindi:

> नमस्ते, मैं किसान सहायक हूँ और आपके खेत के लिए बारिश तथा फसल-सुरक्षा की ताज़ा सूचना देने के लिए कॉल कर रही हूँ। भविष्य की कॉल रोकने के लिए कभी भी “कॉल बंद करें” कहें।

English responses remain English. Hindi responses use Devanagari, never romanized Hindi. Roman Hindi detected during the outbound call is answered in Devanagari Hindi to satisfy the Day 6 native-script rule. Tool values and timestamps are preserved exactly.

## Components and data flow

`backend/src/telephony/outbound/call_config.py` owns the pure call contract: supported languages, metadata serialization and parsing, greetings, destination validation, and quiet-hours enforcement.

`backend/src/telephony/outbound/dial.py` is the operator CLI. It validates consent and destination safety, checks persistent opt-out state, creates a unique LiveKit room, and dispatches `outbound-agent` with JSON metadata.

`backend/src/telephony/outbound/agent.py` is a separate LiveKit worker. It validates dispatch metadata, warms the voice session while dialing, creates the SIP participant through `LIVEKIT_SIP_OUTBOUND_TRUNK_ID`, speaks the compliant greeting after answer, exposes live-weather, opt-out, voicemail, and end-call tools, and uses Murf Falcon with the Anisha voice.

`backend/src/db.py` adds a small `outbound_opt_outs` table. The opt-out tool records the exact destination, and the dialer refuses later calls to it.

The call flow is:

1. The operator starts the outbound worker.
2. The operator runs `dial.py` for a controlled Linphone username and confirms consent.
3. The dialer performs safety checks and dispatches the worker.
4. The worker asks LiveKit SIP to call Linphone and waits for an answer.
5. The agent speaks its identity, purpose, and stop instruction in the selected language.
6. The agent calls the live-weather tool and speaks the timestamped advisory naturally.
7. The recipient can ask a farming question, opt out, or end the call.

## Failure behavior

Missing trunk configuration or invalid metadata stops the worker without dialing. Busy, declined, timeout, and other SIP failures are logged with the available SIP status, the warming session is cancelled, and the worker shuts down. Weather timeouts produce an explicit spoken message that live weather is unavailable and no values are guessed. Voicemail detection ends the call instead of leaving a message. Database failures do not falsely claim that an opt-out was saved.

## Configuration and documentation

`backend/.env.example` documents `LIVEKIT_SIP_OUTBOUND_TRUNK_ID`. A checked-in Linphone trunk example contains no credentials. The root and backend READMEs explain account creation, trunk creation, the required Linphone media-encryption setting, worker startup, the safe dial command, a Hindi demo, graceful-failure demonstrations, and the exact remaining steps that require the user's account.

## Testing

Deterministic tests cover metadata round-tripping, native-script greetings, invalid destinations, missing consent, quiet hours, opt-out persistence, repeat-call blocking, and the live-weather failure path. API construction is kept behind a small dial function so tests can validate all pre-dispatch behavior without making a real call. Ruff, deterministic pytest tests, and a CLI dry run must pass before handoff. A real SIP call remains the final integration test because it requires the user's Linphone username and LiveKit trunk ID.
